TCP滑动窗口机制

TCP 的滑动窗口机制（Sliding Window）是实现高效传输 + 流量控制 + 拥塞控制基础的核心机制之一。可以把它理解为：发送方不用等每个包确认，就可以连续发送多个数据包，但数量受到窗口大小限制。

一、为什么需要滑动窗口？

如果没有滑动窗口，TCP 只能这样：

问题：

  • RTT（往返时间）一高 → 吞吐量极低
  • 网络带宽利用率非常差

滑动窗口解决：允许“批量发送 + 批量确认”

二、核心概念

2.1 窗口（Window）

窗口本质是一个缓冲区范围，表示：

发送方在未收到ACK之前，最多可以发送多少字节的数据

2.2 发送窗口（Send Window）

发送窗口包含三部分：

  • 已发送已确认：可以丢弃
  • 已发送未确认：等待 ACK
  • 可以发送：窗口允许范围内的数据

这就是流量控制（Flow Control）

5.2 流量控制（Flow Control）

接收方控制发送方速度：

  • 接收窗口大 → 发快一点
  • 接收窗口小 → 慢一点
  • 接收窗口 = 0 → 停止发送（窗口关闭）

八、常见面试延伸问题

8.1 为什么窗口是“字节”而不是“包”？

TCP 是面向字节流的协议

2：窗口太大有什么问题？

  • 接收方处理不过来
  • 网络可能拥塞

3：窗口太小？

  • 吞吐量低
  • 带宽浪费
